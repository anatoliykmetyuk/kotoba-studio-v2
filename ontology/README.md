# Kotoba ontology and Neo4j profile

`src/*.oml` is the authoritative ontology. It separates corpus, learning, provenance, media, and operational concepts. Identifiers are globally unique UUID strings. `identityKey` is a managed deduplication key, not a human label. A canonical Word links to itself through BASE_FORM; forms share its learning-status family. Word has an OML key on exact surface spelling, enforced by Neo4j uniqueness and the graph validator. HAS_MEANING connects Words to separate Meaning entities identified by dictionary source/sense plus gloss, reading, and part of speech. Multiple alternatives are displayed together. Contextual WordOccurrences are owned by a SentenceOccurrence, so identical sentence text can appear in multiple texts with different positions and readings. Phrase membership is an ordered graph of PhraseMember nodes, not an opaque list of IDs.

Run `uv run python scripts/compile_ontology.py`. It runs the official openCAESAR OML validator/converter through the pinned Gradle wrapper, then compiles the official JSON AST to `compiled.json`. The source digest binds the runtime database to the ontology. Unsupported constructs fail compilation rather than silently disappearing.

This is a closed-world property-graph profile of OML, not a general OWL inference engine. The supported subset is concrete concepts specializing Entity, functional scalar properties, string enumerations, unreified relationships, unique keys, and exact-one cardinality restrictions. Every runtime node has Entity and exactly one concrete label. Properties not included in its concept restrictions are forbidden. Core scalar properties have Entity as their reusable domain; concept restrictions close the actual per-concept shapes.

Neo4j Community enforces UUID and identityKey uniqueness through constraints. Additional property/cardinality rules are enforced transactionally by the service because Community does not expose all Enterprise existence/type constraints. Cross-entity invariants in `api/schema.py` enforce canonical roots, both learning areas, occurrence ownership/offsets, ordered phrase references, and deduplication. These application-level constraints supplement OML and are tested. JSON payloads are reserved for opaque operational/provenance data, not corpus relations.

A single short Schema write lock serializes mutations. Typed scalar changes validate a restricted property allowlist and complete node shape, without fetching all nodes. Topology changes and generic Cypher writes validate the full graph before commit. This deliberate tradeoff favors correctness for a personal corpus; full imports and audits are more expensive than status changes. Indexes cover Entity IDs/keys, frequent concrete IDs, Word spelling, and job state/creation time. Query benchmarks are recorded in the acceptance report.

All graph writes should use the API. Bolt is private to the Compose network in production. Schema evolution is explicit through `./kotoba schema-plan` and `schema-apply`, with a backup and atomic data transformation. An API with a different source digest fails to start or write.
