# Kotoba Studio v2

## Authorization and boundaries
The user grants standing permission to commit and push work for this project, including future implementation and fixes. Commit each significant completed fix or feature as a coherent change. Before finishing a work turn, push all accumulated commits; pushing after every individual commit is optional. Verify the relevant checks and audit reachable history for credentials and private data before pushing. If a push is blocked, report the specific blocker and retain it as unfinished. Never attribute commits to AI. Worktrees belong under `.agents/worktrees/` in this repository.

Never modify the previous application directory (`../kotoba-studio` in the original installation), its data, the user's writing journals, or existing Ollama configuration. Test with disposable databases, media directories, and browser contexts. Preserve protected-file checksums.

## Product contract
Read `docs/implementation.md` for the accepted plan and current implementation ledger. No Writing functionality or journal migration. No daily targets, goals, points, streaks, related UI, schema fields, or migrated goal-system records. Ordinary reading progress and learning statuses remain. Identical entities deduplicate. A Word is uniquely identified by exact spelling (surface), with a stable UUID. Separate Meaning entities hold its multiple dictionary/user/legacy meanings and translations; display them together on word click. Never create separate Words for different meanings of the same spelling. Every Word links to one canonical base Word, which links to itself. All forms share Reading and Listening status through that base. Import uses only local tokenization and the built-in dictionary; never use model inference during import. Word details reuse stored Meanings first, consult the dictionary only when no meanings exist, then use the local LLM only if the dictionary has no entry. Persist that fallback as a Meaning and reuse it; never use a model to choose among dictionary alternatives. Sentence translation and word/sentence pronunciation are lazy, requested on demand and cached. Agents must import through POST /api/v1/imports and inspect GET /api/v1/jobs/{id}; expose real progress, stage counts, timing, ETA, and stalled/error information. Text status is independently New or Completed. Explicit completion previews the number of unique base families with New in either Listening or Reading, then confirms promotion to Known in both areas. Families without New retain their statuses. All forms share the resulting statuses. Reopening a Text is status-neutral. Already completed lessons can explicitly mark remaining New words Known; never apply that retroactively without the user action.

## Ontology and agents
OML in `ontology/` is the authoritative graph schema. Use official OML tooling and generated validation; never maintain a competing hand-written graph schema. All writes, including agent Cypher, must pass transactional conformance checks. Use the local [kotoba-graph skill](.agents/skills/kotoba-graph/SKILL.md) for querying, changing, or maintaining corpus data.

## Verification
Use shared isolated fixtures. Prove domain behavior in unit/integration tests and actual service boundaries in real-stack tests. No route mocks in final acceptance. Verify mobile Chromium, phone WebKit, and iPad WebKit over the actual Tailscale origin, in portrait and landscape. Inspect screenshots as well as automated layout and interaction assertions. Test recovery, persistence, speech, schema enforcement, and agent operations. Record timings; the warmed acceptance matrix targets 20 minutes. Do not assign manual verification to the user.

## Reader design and review budget
The reader should feel like an e-book: continuous paragraphs, modest default type, compact paragraph spacing, and no per-sentence toolbars or “read to here” controls. Font size and line spacing must be configurable under reader options and persist across devices. Progress saves automatically. Put sentence meaning/audio in the selected-word context panel.

Tapping a word displays its canonical base form, meanings, and family details, and automatically plays the base form pronunciation and changes New to Learning atomically in both Listening and Reading, without downgrading Familiar/Known. Phrase selection must not promote learning statuses or pronounce individual tokens. Show the first three dictionary meanings by default with an explicit expansion control. Long-press and drag selects contiguous tokens across lines/sentences; disable native OS selection and callouts only in the reader. Temporary selected phrases use fresh local translation and speech per request, without persistent graph/media caching. Opening a selected phrase automatically generates one read-only translation and starts speech in the selection gesture. The phrase popup contains only the selected text, translation/loading/error text, close control, and the same speaker icon used for word pronunciation. Never add editable translation fields, Save phrase, or Translate again controls to this popup. Tokens use distinct background highlights for New, Learning, and Familiar; Known is unhighlighted. Verify actual media playback, not merely successful audio downloads.

Every UI label must be strictly factual and functional. No marketing language, slogans, punchlines, motivational copy, decorative taglines, or congratulatory flourishes anywhere in the UI. Use direct labels, factual feedback, and only instructions needed to operate a feature. Let the layout and controls explain themselves. User steering adds constraints or corrections to the active plan; continue implementing the plan with those corrections until it is complete.

At important implementation checkpoints, spawn a fresh-context reviewer to evaluate correctness, architecture, query efficiency, and ontology/database practices. Keep review plus optional refactoring at or below 20% of effort; at least 80% should deliver the plan. Prioritize demonstrated defects over speculative redesign.

## Mobile, practice, and PWA corrections
Listening precedes Reading in status controls and area filters. Popup dismissal gestures accept touch input only, never mouse dragging. Hide the drag handle on devices with a fine mouse pointer. A downward touch swipe anywhere on a popup dismisses it only if that gesture begins at the topmost scroll position. If content is scrolled, the entire gesture scrolls without dismissing, even when it reaches the top. Sliders retain their own drag gestures. Popup scrolling must never scroll the underlying lesson. Example navigation targets the exact placement and briefly highlights it yellow, fading away. Practice advances automatically after short correct feedback, freshly shuffles choices and distractors, and prepares sentence translation and all challenge pronunciation before displaying sentence reconstruction. Each clicked token plays cached audio immediately. This preparation is requested by entering practice; ordinary reading audio and translation remain lazy. Cached speech requests must be read-only indexed lookups, without a graph-wide audit.

Serve the installable PWA using Tailscale-managed trusted HTTPS, never a self-signed certificate or a certificate-warning bypass. Use custom HTTPS port 3010, never default port 443. Keep upstream HTTP bound only to loopback; do not bind Docker HTTP to the Tailscale address on the HTTPS port. Verify mobile and standalone layouts, service-worker updates, offline cached reading, and queued progress recovery. Never claim WebKit offline emulation passed when it is blocked by the documented Playwright service-worker issue.

Settings must provide Check for updates with explicit checking, current and failure results. Show a separate Reload to update action only when an update is ready; never reload automatically while the user is reading. Share update state with the existing banner and keep failed checks retryable.

English/Latin runs are plain noninteractive reader text, never standalone vocabulary entities; preserve them in multi-token phrase selections. Reader settings need 44px slider targets, stable values while holding/releasing, and serialized persistence that cannot roll back newer local edits.

Sticky reader controls must remain below the top device safe area after scrolling; reserve side cutouts after rotation and keep popup controls in the safe viewport. Verify nonzero safe-area insets, because browser device presets alone report zero.

Opening, restoring, or closing a lesson must not advance reading progress. Persist the actual local viewport bookmark independently of monotonic furthest-read progress; restore server-only progress at the same viewport line used when saving it. Popup scroll locks, layout changes, and stale query responses must not create reading activity.

Word details are overlays at every viewport size. On wide screens they open from the right without changing reader width, token positions or reading progress. Lock background scrolling, retain modal keyboard focus and restore the original reading position when closing. Never restore a layout column for this panel. All popup buttons, including close, copy and pronunciation, accept mouse, finger, Apple Pencil and keyboard input, including after a touch scroll or canceled swipe. Clicking or tapping the backdrop dismisses word and phrase popups on desktop and iPad without activating content behind them; dragging must not dismiss them.

Use one application-wide activation abstraction for mouse, finger, pen and keyboard equivalence. Components use ordinary semantic controls and click/change handlers, never their own Apple Pencil workarounds. The shared adapter covers native actions, while scrolling, text input, range dragging and token selection retain their native or dedicated gesture ownership. Verify dialogs, navigation, forms, labels and reader/practice actions together when changing input behavior.

Word and selected-phrase popups must use the same ReadingDetails component, heading/playback/copy controls, scroll container and responsive overlay shell. Selection supports mouse dragging, finger/Pencil long-press dragging, and holding a single token then releasing and tapping an endpoint. Keep the anchor visibly selected until the endpoint or cancellation. Do not restore a Select phrase toolbar button. Icon-only copy controls copy the displayed Japanese word/phrase and the contextual sentence, without ruby annotations. The user approved replacing MeCab/UniDic with Ichiran. Use its existing segmentation and conjugation analysis. Never customize Ichiran token boundaries, grammar rules, or add manual merging; report cases it handles poorly to the user. Prefer upstream configuration to separate grammatical patterns; if unavailable, the user accepts unchanged upstream grouping with the canonical base shown in the popup. Grouping ても is not a requirement. Preserve exact source offsets and whole inflected forms, linked to their canonical bases. Existing-corpus retokenization must preserve source text, learning status, and reading progress with a backup and validated migration.

Practice is lesson-specific. No global Practice navigation or corpus-wide question pool. Questions and distractors belong to the selected Text, and answer APIs validate that membership. Include all statuses by default so a completed lesson remains practiceable. Keep the existing exercise behavior and provide a return to the lesson.

## Persistent storage
All persistent application and Docker service data must live inside this repository under git-ignored `data/` or `.runtime/`. Use bind mounts beneath `data/docker/` for Neo4j data/logs, media, and the Ichiran PostgreSQL database. Never introduce named or anonymous Docker volumes, including image-declared default volumes. Production, acceptance and development must use separate directories. Move existing storage only with stopped database writers, a verified copy, and preservation checks before removing the original volumes.
